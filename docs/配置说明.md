## 配置参考

Agent Relay 通过 Pydantic Settings 读取进程环境和当前工作目录下的 `.env`，环境变量名不区分大小写。生产部署应把 `.env` 权限设为 `0600`，只允许服务账号读取。逗号分隔字段不要使用 shell 数组语法。

## 核心配置

核心配置控制工作区、并发、超时和进程输出边界：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_NAME` | `Agent Relay` | 应用显示名称 |
| `LOG_LEVEL` | `INFO` | JSON 日志级别 |
| `DATABASE_PATH` | `./data/agent-relay.db` | SQLite 文件；建议绝对路径或服务 WorkingDirectory 下的受保护路径 |
| `GENERAL_WORKSPACE` | `~/.agent-relay/general-workspace` | 无项目通用对话使用的隔离空目录；通用对话强制只读且不检查文件 |
| `DEFAULT_WORKSPACE` | 进程启动目录 | Telegram 项目选择器优先展示的默认项目 |
| `WORKSPACE_ROOTS` | `DEFAULT_WORKSPACE` | 逗号分隔的绝对允许根目录；请求路径必须真实存在且解析后位于其中 |
| `MAX_CONCURRENT_RUNS` | `2` | 跨会话 CLI 并发上限，范围 1–32 |
| `RUN_TIMEOUT_SECONDS` | `3600` | 每个只读或执行 phase 的超时 |
| `APPROVAL_TIMEOUT_SECONDS` | `1800` | 计划等待审批的最长时间，到期后任务变为 rejected |
| `PROCESS_INTERRUPT_GRACE_SECONDS` | `5` | 取消时 SIGINT 等待时间 |
| `PROCESS_TERMINATE_GRACE_SECONDS` | `3` | SIGTERM 等待时间，之后 SIGKILL |
| `SUBPROCESS_OUTPUT_LIMIT_BYTES` | `2000000` | 每个 CLI stdout/stderr 本地捕获总上限 |
| `SUBPROCESS_EVENT_LINE_LIMIT` | `5000` | 每个 phase 可转发给事件解析器的 stdout/stderr 行数上限 |
| `MAX_PROMPT_CHARS` | `20000` | 远程 prompt 最大字符数 |
| `MAX_EVENT_TEXT_CHARS` | `8000` | 单个事件字符串最大字符数 |
| `HANDOFF_CONTEXT_CHARS` | `8000` | 跨 Agent 交接上下文最大字符数 |

多个 `WORKSPACE_ROOTS` 示例：

```dotenv
DEFAULT_WORKSPACE=/srv/agent-workspaces/project-a
WORKSPACE_ROOTS=/srv/agent-workspaces/project-a,/srv/agent-workspaces/project-b
```

生产环境优先列举具体项目目录，不要设置 `/`、用户 home 或整个 `/Users`、`/home`。路径解析会消除 symlink 后再检查包含关系，但 allowlist 只控制会话入口，不是 syscall 级隔离。

## Telegram

Telegram 配置控制 long polling、身份白名单、任务卡更新与 Mini App 地址：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TELEGRAM_ENABLED` | `false` | 是否启动 long polling |
| `TELEGRAM_BOT_TOKEN` | 空 | BotFather token；启用时必填 |
| `TELEGRAM_ALLOWED_CHAT_IDS` | 空 | 逗号分隔 chat id；启用时不能为空 |
| `TELEGRAM_ALLOWED_USER_IDS` | 空 | 逗号分隔 user id；启用时不能为空 |
| `TELEGRAM_POLL_TIMEOUT_SECONDS` | `30` | getUpdates long polling 超时，1–50 秒 |
| `TELEGRAM_EDIT_INTERVAL_SECONDS` | `1.5` | 任务卡片最小编辑间隔，至少 0.5 秒 |
| `TELEGRAM_FREE_TEXT_MODE` | `auto` | `auto` 会只读判断后直接回答或请求变更审批；也可设为 `ask` 或 `run` 固定模式 |
| `TELEGRAM_WEBAPP_URL` | 空 | Telegram Mini App 的公开 HTTPS `/app` 地址；配置后自动注册“打开工作台”菜单按钮 |
| `TELEGRAM_MAX_UPDATES_PER_MINUTE` | `30` | 单 user id 的进程内滑动窗口限流 |

白名单使用交集而不是并集。Telegram 限流是单实例内存状态，不是多实例分布式限流；同一 Bot token 本来也只能运行一个 long-polling consumer。

## HTTP API

HTTP API 配置控制业务接口、监听地址和服务端身份映射：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `API_ENABLED` | `true` | 是否启用 `/v1` 业务 API 和 `/docs`；serve 仍启动 ASGI/health 生命周期以承载 Telegram |
| `API_HOST` | `127.0.0.1` | 监听地址；生产建议保留 loopback |
| `API_PORT` | `8787` | 监听端口 |
| `API_BEARER_TOKEN` | 空 | 至少 32 字符的随机业务 API token；未配置时业务端点与 readiness 失败 |
| `API_ACTOR_ID` | `api` | 服务端为该 token 固定映射的 principal；客户端 header 不能覆盖 |

即使 `API_ENABLED=false`，当前实现仍会启动 uvicorn 并保留 health routes，使 Telegram 可以继续运行在同一 ASGI lifespan 中。此时 `/v1` 返回 503，`/docs` 不提供。

该开关不能代替网络 ACL。禁用远端 HTTP 访问时，应保留 loopback、不要发布端口，并使用主机防火墙或服务边界控制。当 API 已启用且 `API_HOST` 不是 `127.0.0.1`、`::1` 或 `localhost` 时，启动配置强制要求 token。

Bearer token 不提供 TLS。跨主机接入必须经过支持 TLS、限流和身份映射的反向代理，或使用 SSH/VPN 隧道；不能直接把端口暴露到公网。

## Agent CLI

Agent CLI 配置控制可执行文件、默认模型、推理强度和子进程工具权限：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CODEX_EXECUTABLE` | `codex` | PATH 中的 Codex CLI 名称或绝对路径；相对路径拒绝 |
| `CODEX_MODEL` | 空 | 可选模型覆盖；空值沿用 CLI 配置 |
| `CODEX_REASONING_EFFORT` | `high` | 传给 Codex 的 reasoning effort 配置 |
| `CLAUDE_EXECUTABLE` | `claude` | PATH 中的 Claude Code CLI 名称或绝对路径；相对路径拒绝 |
| `CLAUDE_MODEL` | `claude-sonnet-5` | Claude 默认完整模型 ID；可覆盖为其他 CLI 支持的固定型号 |
| `CLAUDE_ALLOWED_TOOLS` | `Read,Glob,Grep,Edit,Write,NotebookEdit,Bash` | 执行 phase 的 Claude 工具 allowlist |
| `AGENT_ENV_ALLOWLIST` | 见下文 | 子进程可以继承的环境变量名 |

默认环境白名单为：

```text
HOME,PATH,USER,LOGNAME,SHELL,LANG,LC_ALL,TERM,TMPDIR
```

Runner 会强制设置 `NO_COLOR=1`，并为缺失的 `PATH` 与 `TERM` 提供保守默认值。PATH 处理规则如下：

- 移除空项、相对目录、不存在的目录和全局可写目录；
- 只在清洗后的 PATH 中查找裸 CLI 名称；
- 预检通过后，两个 Adapter 固定执行已经检查的 symlink canonical target；后续重定向原 symlink 不会改变运行目标。

这些规则用于避免远程 workspace 或共享目录通过同名程序劫持命令解析。API key 与 `SSH_AUTH_SOCK` 不在默认白名单中，应优先使用已经登录的 CLI 凭据。确需环境变量认证或 SSH agent 时，只添加必要的变量名，并明确 Agent 子进程及其工具也将获得相应能力。

`CLAUDE_ALLOWED_TOOLS` 是 CLI 工具许可，不是命令级规则。只要允许 `Bash`，Agent 就可能运行范围广泛的命令。需要更强隔离时使用专用用户、严格挂载的容器，或从列表移除 `Bash` 并接受能力下降。不要通过加入危险 CLI 参数来修复兼容问题。

## 建议基线

所有部署方式都从根目录的 [`.env.example`](../.env.example) 复制。模板只保留启动必需项，所有 token 都为空；超时、限流和输出上限沿用代码中的安全默认值，确需调整时再按本页变量表加入 `.env`。生成 API token 后不要在命令输出、工单或聊天记录中回显。
