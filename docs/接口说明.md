## HTTP API 与 SSE

HTTP transport 面向本机程序集成，默认监听 `127.0.0.1:8787`。除两个 health endpoint 外，所有端点都要求：

```
Authorization: Bearer <API_BEARER_TOKEN>
```

该 token 的 owner 由服务端 `API_ACTOR_ID` 固定映射，客户端传入的 `X-Actor-ID` 不参与授权。一个 token 只能视为一个信任域；需要隔离的调用程序应使用独立实例、独立 token 和独立 actor id。

## 端点

HTTP transport 提供健康检查、会话管理、任务控制和事件读取端点：

| 方法与路径 | 鉴权 | 说明 |
| --- | --- | --- |
| `GET /health/live` | 无 | 进程存活，不表示 CLI 或业务可用 |
| `GET /health/ready` | 无 | 数据库、两种 CLI、API token、Telegram transport 和是否接收任务 |
| `GET /v1/agents` | bearer | 适配器能力、CLI 可用性和取消语义 |
| `POST /v1/conversations` | bearer | 创建会话并设为该 actor 当前会话 |
| `GET /v1/conversations` | bearer | 列出该 actor 的会话 |
| `POST /v1/conversations/{id}/agent` | bearer | 无活跃任务时切换 Agent |
| `POST /v1/conversations/{id}/runs` | bearer | 创建 ask 或 run，返回 202 |
| `GET /v1/runs/{id}` | bearer | 获取属于该 initiator 的任务 |
| `GET /v1/runs/{id}/events?after=N` | bearer | 持久事件回读 |
| `GET /v1/runs/{id}/events/stream?after=N` | bearer | SSE 订阅与断点恢复 |
| `POST /v1/runs/{id}/decision` | bearer | approve 或 reject 待审批计划 |
| `POST /v1/runs/{id}/cancel` | bearer | 请求取消，返回 202 |

### 创建会话

```json
{
  "workspace": "/absolute/path/to/project",
  "agent": "codex",
  "title": "optional title"
}
```

`agent` 只能是 `codex` 或 `claude`。workspace 必须存在、是目录，并在 `WORKSPACE_ROOTS` 解析后的范围内。

### 切换 Agent

```json
{
  "agent": "claude"
}
```

切换不会覆盖另一 Agent 的原生 session。当前会话存在 queued/planning/awaiting approval/running/cancel requested 任务时返回 409。

### 创建任务

```json
{
  "mode": "run",
  "prompt": "实现一个健康检查并运行相关测试"
}
```

不同任务模式的状态变化如下：

- `ask` 成功后直接进入 `completed`。
- `run` 先进入 `awaiting_approval`；响应中的 `plan` 只有规划完成后才出现，调用方应通过 GET 或 SSE 等待。
- 计划为空、超过 2400 字、协议解析异常或缺少可恢复 session 时，任务直接进入 `failed`，不会开放审批。

### 决策

```json
{
  "decision": "approve"
}
```

decision 只能是 `approve` 或 `reject`。审批必须来自创建任务时相同的服务端 API principal，而且任务仍处于 awaiting approval。approve 只授权这份计划的一次执行，不会触发逐工具二次确认。

### 取消

取消响应可能仍是 planning、running 或 cancel requested 的旧/过渡状态；调用方必须继续等待 `run.cancelled` 或其他终态。对终态重复取消是幂等读取。取消不回滚已写文件或外部副作用。

## Run 状态

Run 的持久状态及其含义如下：

| 状态 | 含义 |
| --- | --- |
| `queued` | 已持久化，等待并发槽 |
| `planning` | ask 或只读计划 phase 正在运行 |
| `awaiting_approval` | plan 已持久化，等待 initiator 决策 |
| `running` | 获批执行 phase 正在运行 |
| `cancel_requested` | 已发出取消，等待进程组终止 |
| `cancelled` | 已确认停止 |
| `completed` | 成功完成 |
| `failed` | CLI 非零退出或内部错误 |
| `rejected` | 人工拒绝或审批到期 |
| `interrupted` | 服务退出/重启打断，未自动恢复 |
| `timed_out` | phase 超过 `RUN_TIMEOUT_SECONDS` |

终态为 cancelled/completed/failed/rejected/interrupted/timed_out。

## 事件

事件以每个 run 单独递增的 `seq` 排序：

| kind | 典型 payload | 含义 |
| --- | --- | --- |
| `run.queued` | agent、mode | 入队 |
| `agent.started` | phase、agent、可选 session/model | CLI/phase 启动 |
| `agent.status` | status、可选 message | thinking、working、warning、error |
| `output.delta` | text | Claude 文本 delta 或 Codex 完成后的消息块 |
| `tool.started` | tool、tool_call_id、有限输入 | 工具开始 |
| `tool.completed` | tool/tool_call_id、有限结果/状态 | 工具结束 |
| `approval.required` | approval_id、expires_at | 需要审阅整份 plan |
| `approval.decided` | decision、可选 actor | approved/rejected/expired |
| `run.cancel_requested` | actor | 用户要求停止 |
| `run.cancelled` | message | 进程已停止 |
| `run.completed` | phase | 任务成功 |
| `run.failed` | message | 失败 |
| `run.timed_out` | message | 超时 |
| `run.interrupted` | message | 服务重启/停止中断 |
| `agent.usage` | CLI 原生 usage 的安全结构 | token/cost 等，仅在 CLI 提供时出现 |

不要让客户端依赖每个 Agent 都产生完全相同的事件。Codex 没有 token 级输出 delta；Claude 可以产生细粒度文本 delta。客户端应以 run 终态和最终 `plan`/`result` 为准，以事件改善实时体验。

## SSE 约定

每条事件包含 SSE `id`、`event` 与 JSON `data`：

```text
id: 7
event: tool.started
data: {"seq":7,"kind":"tool.started","payload":{},"created_at":0.0}
```

15 秒无事件时服务发送 comment keep-alive。任务进入终态且已有事件发送完后，服务发送：

```text
event: end
data: {}
```

断线重连使用最后成功处理的序号请求 `?after=<seq>`。服务不读取 `Last-Event-ID` header；调用方应显式传 `after`。SSE 数据来自 SQLite，单次列表读取最多 1000 条；高吞吐消费者应及时推进游标。

## 错误语义

客户端应根据 HTTP 状态区分认证失败、资源隔离、状态冲突和服务未就绪：

| HTTP 状态 | 典型原因 |
| --- | --- |
| 401 | 缺少 bearer token |
| 403 | token 错误或 workspace 被拒绝 |
| 404 | 会话/任务不存在，或不属于当前 actor |
| 409 | 活跃任务冲突、状态已变化、审批已处理/过期 |
| 422 | JSON schema、enum 或字段长度错误 |
| 503 | 业务接口未配置 `API_BEARER_TOKEN`，或 readiness 失败 |

创建 run 时还可以传入以下执行参数：

- `permission_mode`：`request_approval`（默认）、`workspace_auto` 或 `full_access`。
- `model`：只能包含字母、数字、点、下划线、冒号和连字符。
- `reasoning_effort`：Codex 支持 `low`、`medium`、`high`、`xhigh`、`max`、`ultra`，Claude 支持到 `max`。

服务端会把无项目通用会话强制降为 `request_approval` 和只读 `ask`。`workspace_auto` 与 `full_access` 都会跳过人工计划批准；API 调用方必须自行承担授权确认责任，Mini App 会对 `full_access` 做二次确认。Run 读取响应会回传最终生效的权限、模型和推理强度。

Mini App 使用以下专用接口：

- `GET /app/api/runs/{run_id}/events`：返回经过重新鉴权和安全过滤的持久事件，用于展示状态、工具调用和增量输出。
- `GET /app/api/runs/{run_id}/files`：返回文件名、项目相对路径、预览类别、媒体类型、大小和可用状态。
- `GET /app/api/runs/{run_id}/files/{file_id}`：返回经过重新鉴权与路径校验的文件内容。

这些接口只服务于 Telegram Mini App，不接受裸公网访问，也不允许读取项目外路径或敏感凭据文件。

客户端在 decision/cancel 竞态中收到 409 后应重新 GET run，而不是盲目重试批准。
